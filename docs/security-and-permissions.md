### Хэрэгжүүлэлт — 3 давхарга

1. **Route** — `authorize(ROLE_GROUP.X)`: бүдүүн ширхэглэлийн шалгалт
2. **Service** — нарийн ширхэглэл: override хязгаар, 24 цагийн цонх, салбарын хамрах хүрээ
3. **UI** — товч нуух: **зөвхөн эвгүй байдлаас сэргийлэх зорилготой, хамгаалалт биш**

```js
// Route — бүдүүн
router.delete('/:packageId', authorize(ROLE_GROUP.ADMIN), ...);

// Service — нарийн (BR-10)
assertDeletable(pkg, actor) {
  if (actor.role !== 'admin') {
    throw new APIError('Зөвхөн админ ачааг устгана', httpStatus.FORBIDDEN);
  }
  if (pkg.paidAmount > 0) {
    throw new APIError('Төлбөртэй ачааг устгах боломжгүй. "Хүчингүй" болгоно уу',
      httpStatus.UNPROCESSABLE_ENTITY);
  }
  const hours = (Date.now() - pkg.createdAt) / 36e5;
  if (hours > settings.deleteWindowHours) {
    throw new APIError('24 цаг хэтэрсэн. "Хүчингүй" болгоно уу',
      httpStatus.UNPROCESSABLE_ENTITY);
  }
}
```

## 3. Салбарын хамрах хүрээ (Branch scoping)

Менежерийн бүх query автоматаар өөрийн салбараар хязгаарлагдана.

```js
// service давхаргад
applyBranchScope(query, actor) {
  if (actor.role === 'admin') return query;
  return { ...query, branchId: actor.branchId };
}
```

**Дүрэм:**
- Frontend-ээс ирсэн `branchId` параметр нь зөвхөн **нэмэлт шүүлт**, эрх өргөтгөх хэрэгсэл биш
- Нэг бичлэг уншихад ч шалгана: менежер өөр салбарын ачааны ID мэдсэн ч `404` авна
- Тайлан, audit log-д мөн адил үйлчилнэ

## 4. Танилт (Authentication)

### JWT

| Талбар | Ажилтан | Харилцагч |
|---|---|---|
| `sub` | `users._id` | `customers._id` |
| `aud` | `staff` | `customer` |
| `role` | `admin`/`manager`/`staff` | — |
| `branchId` | ObjectId | — |
| `exp` | 8 цаг | 30 хоног |

**Заавал:** `aud` шалгагдана. Харилцагчийн токеноор ажилтны endpoint рүү орох боломжгүй,
эсрэгээр ч мөн адил.

### Нууц үг

- bcrypt (salt rounds 10) — `user.model.js`-ийн `pre('save')` hook
- Хариултад `password` **хэзээ ч** орохгүй (`toJSON` transform)
- Хамгийн бага урт **8 тэмдэгт** (одоогийн `minlength: 4`-ийг Phase 0-д өсгөнө)

### Харилцагчийн танилт (Phase 5)

| Зам | Тайлбар |
|---|---|
| Утас + нууц үг | `POST /v1/customer/auth/register` \| `/login`. Утас ЗААВАЛ (BR-26) |
| Google OAuth | `/auth/google` → callback. Бүртгэлгүй бол **түр токен** (`aud: 'customer_pending'`, 15 мин) олгож утсыг нь асууна |
| Токен | `aud: 'customer'`, 30 хоног. `passport`-ийн `jwt-customer` strategy |
| Middleware | `authorizeCustomer()` → `req.customer`. `req.user`-т ТАВИХГҮЙ |

**Google-ээр утасгүй харилцагч ҮҮСГЭХГҮЙ.** Google-ээс утас ирдэггүй, гэтэл утас
бол ачааг холбох цорын ганц түлхүүр — утасгүй бичлэг нь ямар ч ачаатай
холбогдохгүй "хоосон" бүртгэл болно. Түр токен нь гарын үсэгтэй тул сервер талд
түр төлөв хадгалах шаардлагагүй, засварлах ч боломжгүй.

### OTP (утас баталгаажуулах) — ⛔ ХЭРЭГЖЭЭГҮЙ (roadmap 5.2)

| Дүрэм | Утга |
|---|---|
| Урт | 6 орон |
| Хүчинтэй хугацаа | 5 минут |
| Оролдлого | 3 удаа |
| Хүсэлтийн давтамж | 1 утсанд 1 минутад 1 удаа, өдөрт 10 удаа |
| Хадгалалт | Hash хэлбэрээр |

> ⚠ **ОДООГИЙН НЭЭЛТТЭЙ ЭРСДЭЛ.** SMS үйлчилгээ үзүүлэгч сонгоогүй тул OTP
> Phase 6-д хийгдэнэ. Түүнийг хүртэл бүртгүүлэхэд утас баталгаажихгүй —
> **хэн нэгэн өөрийн бус дугаар бичээд тэр хүний ачаа, үнэ, төлбөрийг харах
> боломжтой.** Эзэмшигчийн шийдвэрээр хүлээн зөвшөөрсөн (2026-07-31).
>
> Хязгаарлах арга хэмжээ:
> - `phoneVerified` нь `false` хэвээр — систем худал бичихгүй. Phase 6-д
>   зөвхөн хаалтыг асаана (BR-28), өгөгдөл засах шаардлагагүй.
> - Харилцагч утсаа **өөрөө солих зам байхгүй** (`updateProfile`-д `phone`
>   талбар БАЙХГҮЙ). Байсан бол нэг бүртгэлээр дараалан утас сольж бүх хүний
>   ачааг харах боломж үүснэ. Утас солих нь ажилтны үйлдэл, audit-д бичигдэнэ.

## 5. Audit Log (§9.2)

### Зорилго

Хэн, хэзээ, ямар өөрчлөлт хийснийг бүрэн хянах; маргаан гарахад нотолгоо болох.

### Дүрмүүд

| Дүрэм | Тайлбар |
|---|---|
| **Append-only** | Засах/устгах боломжгүй. Mongoose hook + DB эрхээр хамгаална |
| **Атомик** | Өөрчлөлттэй нэг транзакцад. Audit бичигдэхгүй бол өөрчлөлт ч хийгдэхгүй (BR-41) |
| **Actor-ын нэр хуулагдана** | Ажилтан устсан ч түүхэнд нэр үлдэнэ |
| **Хугацаа** | Доод тал нь 3 жил. TTL index байхгүй |
| **Экспорт** | Excel / PDF |
| **Шүүлт** | Ачаа, ажилтан, огноо, үйлдлийн төрлөөр |

### Бичлэгийн жишээ

| Талбар | Утга |
|---|---|
| `createdAt` | `2026-07-29T07:22:14Z` |
| `actorName` | Бат |
| `action` | `package.price_override` |
| `entityLabel` | `TRK-88213` |
| `field` | `finalPrice` |
| `before` / `after` | `35000` / `29000` |
| `reason` | "Хэрэглэгчтэй тохиролцсон хямдрал" |

Бүрэн жагсаалт: [`data-model.md` §13](data-model.md).

## 6. Оролтын хамгаалалт

| Заналхийлэл | Хамгаалалт | Байршил |
|---|---|---|
| NoSQL injection | `mongo-sanitize` | `middlewares/sanitize.js` |
| Хүчингүй оролт | Joi схем | `middlewares/validate.js` |
| XSS | Vue-ийн автомат escape; `v-html` **хориотой** | Frontend |
| CSRF | JWT header-т (cookie биш) → CSRF эрсдэлгүй. `express-session` Phase 5-д БҮРЭН устсан — танилт бүхэлдээ JWT дээр | — |
| Хувийн мэдээлэл нээлттэй гарах | `public.service.js` ба `customer-portal.service.js`-ийн **цагаан жагсаалт** | Backend |
| Их биетэй хүсэлт | `express.json({ limit: '10mb' })` | `services/express.js` |
| Brute force | `authLimiter` (login/register) | `middlewares/rate-limit.js` |
| Ерөнхий DoS | `globalLimiter` | `services/express.js` |
| HTTP толгой | `helmet` | `services/express.js` |
| CORS | Зөвхөн `.env`-д заасан origin | `services/express.js` |

### Rate limit-ийн зөвлөмж

| Хүрээ | Хязгаар |
|---|---|
| Глобал | 15 минутад 100 хүсэлт / IP |
| Login / register (ажилтан ба харилцагч) | `authLimiter` — 15 минутад 20 оролдлого / IP |
| **Нээлттэй зам (`/v1/public/*`)** | `publicLimiter` — 15 минутад 120 хүсэлт / IP |
| OTP хүсэх | 1 минутад 1 / утас *(Phase 6)* |
| Ачаа бүртгэх (ажилтан) | **Хязгаарлахгүй** — §1.4-ийн хурдны шаардлагыг зөрчинө |
| QPay webhook | Чөлөөлөгдөнө |

> `publicLimiter` нь ЗААВАЛ: ачаа хайх нь танилтгүй, дугаараар л ажилладаг тул
> хязгааргүй бол дугаарын орон зайг дараалан туршиж (`ABC0001`, `ABC0002`, …)
> аль дугаар бодитоор бүртгэлтэйг, улмаар маскласан утасны эхний 4 оронг
> цуглуулах боломжтой.
